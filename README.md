# Бот «Чистая вода в аудиториях МАИ»

Telegram-бот проекта по установке кулеров с питьевой водой в учебных корпусах МАИ.
Написан на Python: библиотека **pyTelegramBotAPI (Telebot)** для работы с Telegram и **SQLAlchemy** для базы данных (SQLite).

## Что умеет бот

| № | Функция | Как это выглядит |
|---|---------|------------------|
| 1 | **Где кулеры** | Список корпусов → кулеры на этажах → карточка: место, статус, когда меняли бутыль, оценка |
| 2 | **Сообщить о проблеме** | Кнопки «закончилась вода», «не работает», «грязно», «другое». Сообщение сразу уходит ответственному, статус кулера меняется |
| 3 | **Журнал обслуживания** | Ответственный нажимает «заменил бутыль», «провёл дезинфекцию», «ремонт выполнен» — бот записывает дату и закрывает обращения |
| 4 | **Отзывы и опрос** | Оценка кулера 1–5 с комментарием; кнопка «Читать отзывы» в карточке показывает последние 10 отзывов (без имён авторов); повторный опрос из двух вопросов для показателей проекта |
| 5 | **Уведомления** | Подписчики узнают о новых кулерах и получают приглашение на опрос |
| 6 | **Правила и статистика** | Правила пользования, регламент и открытая сводка: сколько кулеров работает, сколько бутылей заменено, как быстро закрывают обращения |

Роли пользователей: **студент**, **ответственный** за кулеры, **администратор**.

QR-код на табличке кулера ведёт сразу на его карточку в боте (ссылка вида `https://t.me/имя_бота?start=cooler_1`).

## Запуск

Нужен Python 3.10 или новее.

1. **Создайте бота.** В Telegram напишите [@BotFather](https://t.me/BotFather): команда `/newbot`, затем название и имя бота (имя должно заканчиваться на `bot`). BotFather пришлёт токен — длинную строку вида `123456:ABC...`.

2. **Установите зависимости.** В папке проекта:

   ```
   python -m venv .venv
   .venv\Scripts\activate        (Windows)
   source .venv/bin/activate     (macOS / Linux)
   pip install -r requirements.txt
   ```

3. **Заполните настройки.** Скопируйте файл `.env` в `.env` и вставьте токен в строку `BOT_TOKEN=`.

4. **Запустите бота.**

   ```
   python run.py
   ```

   При первом запуске создаётся база `voda.db` с двумя корпусами и шестью пилотными кулерами в статусе «планируется».

5. **Сделайте себя администратором.** Напишите боту `/id`, скопируйте число, вставьте его в `.env` в строку `ADMIN_IDS=` и перезапустите бота. Команда `/admin` покажет список команд администратора.

Бот работает, пока запущена программа. Для постоянной работы его запускают на сервере (подойдёт самый дешёвый VPS).

## Команды администратора

| Команда | Что делает |
|---------|-----------|
| `/addbuilding Название \| адрес` | добавить корпус |
| `/addcooler номер_корпуса \| этаж \| место` | добавить кулер со статусом «планируется» |
| `/launch номер_кулера` | ввести кулер в работу и уведомить подписчиков |
| `/assign номер_кулера telegram_id` | назначить ответственного |
| `/setrole telegram_id student\|responsible\|admin` | изменить роль |
| `/qr номер_кулера` | получить табличку с QR-кодом для печати (PNG, формат A5) |
| `/survey_start название` | запустить волну опроса и позвать подписчиков |
| `/survey_stop` | остановить опрос |
| `/survey_stats название` | результаты волны: доля пьющих регулярно, доля оценок 4–5 |
| `/broadcast текст` | сообщение всем подписчикам |
| `/export` | выгрузить журнал, обращения и отзывы в CSV (открываются в Excel) |
| фото с подписью `/photo номер_кулера` | прикрепить фотографию к карточке кулера |

## Как устроен код

```
run.py              запуск бота
config.py           настройки из файла .env
bot/
  models.py         таблицы базы данных
  db.py             подключение к базе и начальные данные (пилотные кулеры)
  services.py       вся логика: обращения, журнал, отзывы, опрос, статистика
  handlers.py       обработчики сообщений и кнопок Telegram
  keyboards.py      клавиатуры
  texts.py          тексты и подписи кнопок
  qr.py             генерация таблички с QR-кодом
tests/              автоматические тесты
```

Таблицы базы: `buildings` (корпуса), `coolers` (кулеры), `users` (пользователи и роли), `reports` (обращения), `service_log` (журнал обслуживания), `feedback` (отзывы), `survey_answers` (ответы на опрос), `settings` (текущая волна опроса).

Логика отделена от Telegram: функции в `services.py` получают сессию базы и ничего не знают о боте. Поэтому их можно проверять тестами без интернета.

## Регламент, который контролирует бот

- бутыль меняют не реже раза в неделю;
- дезинфекция — не реже раза в квартал;
- обращение закрывают за сутки.

В разделе «Обслуживание» ответственный видит открытые обращения и кулеры, по которым сроки нарушены.

## Тесты

```
python -m pytest
```

Тесты не обращаются к Telegram: вместо него подставляется заглушка (`tests/fake_telegram.py`), которая присылает боту сообщения и нажатия кнопок и запоминает его ответы. Проверяется полный сценарий пилота: от QR-кода на табличке до закрытого обращения, отзыва и опроса.
